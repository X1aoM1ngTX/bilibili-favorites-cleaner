# B站收藏夹清理工具 — 项目需求分析

## 1. 项目背景

### 1.1 痛点分析

B站收藏夹用户长期使用后普遍面临以下问题：

- **失效视频堆积**：被删除、下架、审核未通过的视频残留在收藏夹中，无法批量清理
- **收藏夹容量限制**：每个收藏夹最多 1000 个视频，超出后无法再收藏新内容
- **手动排序困难**：B站原生不支持拖拽排序收藏夹，调整顺序非常繁琐
- **跨夹整理低效**：无法批量移动视频到其他收藏夹

### 1.2 项目目标

构建一个**一站式B站收藏夹管理工具**，提供：

- 一键清理失效视频
- 跨收藏夹批量移动视频
- 拖拽排序收藏夹顺序
- 简单易用的操作界面

---

## 2. 用户角色与场景

### 2.1 目标用户

- B站重度用户，拥有多个收藏夹
- 收藏夹内视频数量大（数百到上千）
- 需要定期整理收藏内容的用户

### 2.2 核心使用流程

```
登录认证 → 查看收藏夹列表 → 选择操作（清理/移动/排序）→ 执行 → 查看结果
```

### 2.3 典型场景

| 场景 | 描述 | 频率 |
|------|------|------|
| 定期清理 | 用户定期清理各收藏夹中的失效视频 | 每周/每月 |
| 容量管理 | 某个收藏夹接近1000上限，需移动部分视频到其他夹 | 不定期 |
| 重新排序 | 新建收藏夹后调整所有收藏夹的显示顺序 | 低频 |

## 3. 功能需求

### P0 — 核心功能（必须有）

#### 3.1 登录认证

| 项目 | 说明 |
|------|------|
| 功能 | 通过Cookie完成B站身份认证 |
| 输入 | 用户手动粘贴Cookie字符串 |
| 处理 | 自动解析提取 `bili_jct`（CSRF token）、`DedeUserID`（用户UID） |
| 输出 | 登录状态指示，配置自动保存 |
| 规则 | Cookie中必须包含 `SESSDATA`、`bili_jct`、`DedeUserID` |

#### 3.2 收藏夹列表

| 项目 | 说明 |
|------|------|
| 功能 | 展示用户所有收藏夹 |
| 展示信息 | 收藏夹名称、视频数量、类型（默认/普通/私密） |
| 排序 | 按B站原始顺序展示 |
| 规则 | 使用 `up_mid`（用户UID）获取列表 |

#### 3.3 清理失效视频

| 项目 | 说明 |
|------|------|
| 功能 | 批量清理收藏夹中的失效视频 |
| 输入 | 选择一个或多个收藏夹 |
| 操作 | 支持全选/取消全选 |
| 反馈 | 实时显示每个收藏夹的清理进度和清理数量 |
| 规则 | 调用B站 `/x/v3/fav/resource/clean` 接口 |

#### 3.4 移动视频

| 项目 | 说明 |
|------|------|
| 功能 | 将视频从源收藏夹移动到目标收藏夹 |
| 输入 | 选择源收藏夹、目标收藏夹 |
| 容量检查 | 目标夹视频数 + 待移动数 ≤ 1000 |
| 反馈 | 显示可移动数量、移动结果 |
| 规则 | 每次移动 20-40 个资源，视频类型为 `2` |

#### 3.5 排序收藏夹

| 项目 | 说明 |
|------|------|
| 功能 | 拖拽调整收藏夹的显示顺序 |
| 保护 | 默认收藏夹（attr=0）固定在第一位，不可移动 |
| 操作 | 拖拽排序 + 上下箭头微调 |
| 反馈 | 排序结果提示（成功/失败） |
| 规则 | 一次最多排序 20 个收藏夹 |

### P1 — 增强功能

#### 3.6 收藏夹详情查看

- 查看收藏夹内视频列表
- 展示视频标题、UP主、封面、时长、收藏时间
- 支持分页加载（每页最多 40 条）

#### 3.7 Cookie 智能解析

- 自动从Cookie字符串中提取关键字段
- Cookie格式校验和错误提示
- Cookie过期检测（通过调用API验证）

#### 3.8 操作结果反馈

- 清理：显示每个夹清理了多少失效视频
- 移动：显示移动成功/失败的视频列表
- 排序：显示排序是否生效

### P2 — 可选功能

#### 3.9 QR码扫码登录

- 显示B站登录二维码
- 轮询扫码状态
- 扫码成功后自动获取Cookie

#### 3.10 收藏夹搜索

- 按关键词搜索收藏夹内的视频（标题/UP主）

#### 3.11 Cookie 转换

- 将Cookie转换为 TinyDB 格式（供其他工具使用）

## 4. 业务规则汇总

| 规则 | 说明 | 来源 |
|------|------|------|
| 收藏夹容量上限 | 每个收藏夹最多 1000 个视频 | B站限制 |
| 默认收藏夹保护 | attr=0 的收藏夹排序时固定首位 | B站规则 |
| CSRF 保护 | 所有写操作需提供 `bili_jct` 作为 csrf 参数 | B站安全策略 |
| 移动批量限制 | 一次移动建议 20 个资源，最多 40 个 | 实践经验 |
| 排序批量限制 | 一次排序最多 20 个收藏夹 | B站限制 |
| API 频率限制 | 需控制调用频率，避免触发 -509 限流 | B站风控 |
| 资源类型标识 | 视频类型固定为 `2` | B站API约定 |
| 分页大小 | 收藏夹内容获取每页最大 40 条 | B站API限制 |

## 6. 历次重构问题分析

### 6.1 old 版本（Node.js + 原生JS）

- **优点**：简单直接，快速实现
- **问题**：功能单一（只有清理），无移动和排序功能；原生JS无组件化，难扩展
- **教训**：架构设计需考虑后续功能扩展

### 6.2 new 版本（Vue 3 + Express 前后端分离）

- **优点**：功能完整（清理+移动+排序），Vue 3 组件化，Pinia 状态管理
- **问题**：需同时启动前后端两个服务，部署和用户体验复杂；Express 后端主要是 API 代理，增加了一层不必要的复杂度
- **教训**：对于纯API代理场景，前后端分离架构过重

### 6.3 app 版本（Tauri 2 + Vue 3 + Rust）

- **优点**：桌面应用体验，无需浏览器；Rust 后端性能好
- **问题**：Rust 后端开发维护成本高；Tauri 生态不如 Web 生态成熟；调试困难；iframe 登录方案不够优雅
- **教训**：技术选型需权衡团队能力和维护成本，Rust 对于本项目属于过度设计

### 6.4 nextjs 版本（Next.js 16 + React 19）

- **优点**：全栈统一，API Routes 消除前后端分离复杂度；TypeScript 类型安全；React 19 生态成熟；Zustand 轻量状态管理
- **问题**：QR码登录功能未完成；UI组件手写而非使用组件库，开发效率受限
- **教训**：功能完整度需优先于技术栈的新颖度

### 6.5 总结

| 失败原因 | 涉及版本 |
|----------|----------|
| 架构过重（双服务部署） | new |
| 技术栈维护成本过高 | app |
| 功能不完整就切换方向 | old, nextjs |
| 缺乏清晰的需求文档 | 全部 |

**核心结论**：需要一个功能完整、架构简单、易于维护的方案。不应追求技术新颖度，而应关注交付效率。
